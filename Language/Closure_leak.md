# 클로저 - 메모리 누수 위험성

클로저는 외부 변수를 캡처하여 함수가 해당 변수를 계속 사용할 수 있도록 한다.

클로저 자체가 메모리 누수를 일으키는 것은 아니지만, **캡처한 객체를 필요 이상으로 오래 유지하면 메모리 누수의 원인**이 될 수 있다.

---

## 1. 메모리 유지

```csharp
LargeObject obj = new LargeObject();

Action action = () =>
{
    obj.DoSomething();
};
```

람다식이 `obj`를 캡처한다.

```text
Action
  ↓
Closure
  ↓
obj
```

`action`이 오래 유지되면 `obj`도 함께 유지될 수 있다.

---

## 2. 이벤트와 클로저

특히 **이벤트에 클로저를 등록할 때 주의**해야 한다.

```csharp
publisher.OnEvent += () =>
{
    Console.WriteLine("Event");
};
```

이벤트를 가진 객체가 클로저를 계속 참조하면 캡처된 객체 역시 GC가 회수하지 못할 수 있다.

```text
Publisher
   ↓
 Event
   ↓
Closure
   ↓
Object
```

필요하지 않은 시점에 이벤트 구독을 해제해야 한다.

```csharp
publisher.OnEvent -= handler;
```

익명 람다를 직접 등록했다면 나중에 동일한 람다를 작성해서 해제할 수 없으므로, 필요하다면 델리게이트를 변수에 저장한다.

---

## 3. 큰 객체 캡처 주의

장기간 유지되는 클로저에서 큰 객체를 캡처하면 해당 객체도 오래 유지될 수 있다.

```csharp
LargeData data = GetData();

Action action = () =>
{
    Console.WriteLine(data.Name);
};
```

가능하다면 **필요한 값만 캡처**한다.

---

## 4. 반복적인 클로저 생성

반복문에서 클로저를 대량으로 생성하고 보관하면 불필요한 메모리 할당과 GC 부담이 발생할 수 있다.

```csharp
for (int i = 0; i < 100000; i++)
{
    int index = i;

    actions.Add(() => Console.WriteLine(index));
}
```

클로저를 생성하는 것 자체보다 **생성된 클로저를 불필요하게 오래 보관하는 것**이 중요하다.

---

## 5. 핵심 정리

| 상황                | 주의점              |
| ----------------- | ---------------- |
| 외부 객체 캡처          | 객체의 수명이 길어질 수 있음 |
| 이벤트 + 클로저         | 구독 해제 필요         |
| 큰 객체 캡처           | 필요한 값만 캡처        |
| 반복적인 클로저 생성       | 불필요한 할당 및 GC 부담  |
| 클로저가 더 이상 사용되지 않음 | GC가 회수 가능        |

### 기억할 것

```text
클로저 자체 ≠ 메모리 누수

외부 객체 캡처
      ↓
클로저가 오래 유지됨
      ↓
객체도 계속 참조됨
      ↓
GC가 회수하지 못함
```

> **핵심: 무엇을 캡처하는지, 얼마나 오래 유지되는지 확인하자.**
