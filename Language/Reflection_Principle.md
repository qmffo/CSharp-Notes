# 리플렉션 - 런타임에서 타입 정보를 가져오는 원리

## 1. 핵심 원리

C#은 컴파일할 때 타입에 대한 정보를 **메타데이터(Metadata)** 형태로 어셈블리에 저장한다.

리플렉션은 프로그램 실행 중 이 메타데이터를 읽어 타입 정보를 확인한다.

```text
C# 코드
   ↓
컴파일
   ↓
IL + 메타데이터
   ↓
프로그램 실행
   ↓
메타데이터 조회
   ↓
타입 정보 확인
```

---

## 2. 메타데이터란?

메타데이터는 **코드 자체가 아니라 코드에 대한 정보**이다.

예를 들어 다음과 같은 코드가 있다.

```csharp
class Player
{
    public int hp;

    public void Attack()
    {
    }
}
```

컴파일 과정에서 `Player` 타입에 대한 정보가 메타데이터에 기록된다.

```text
Player
 ├─ 타입 이름
 ├─ 필드 정보
 ├─ 메서드 정보
 └─ 접근 제한자 등
```

---

## 3. 런타임에서 조회되는 과정

객체의 타입을 확인해야 할 때 런타임의 리플렉션 API가 어셈블리에 저장된 메타데이터를 조회한다.

```text
객체
 ↓
실제 타입 확인
 ↓
해당 타입의 메타데이터 조회
 ↓
타입 정보 반환
```

따라서 리플렉션은 **코드를 새로 분석하는 것이 아니라 컴파일 과정에서 저장된 메타데이터를 이용하는 것**이다.

---

## 핵심 요약

> **컴파일 → 타입 정보가 메타데이터로 저장 → 런타임에 리플렉션이 메타데이터를 조회**

즉, 리플렉션이 런타임에 타입을 알아낼 수 있는 이유는 **컴파일된 어셈블리에 타입 정보가 메타데이터로 함께 저장되어 있기 때문**이다.
